# M1 · 学习与查询线

你负责把 M0 存下来的数据变成用户**看得见、用得上**的东西。你的模块最贴近用户，
界面糊了用户第一句就骂这里。

## 你的活（按队列顺序）

| 任务 | 模块 | 一句话 |
| --- | --- | --- |
| T02 | `variant_chars` | 繁简 / 异体对照，一简对多繁要按词选（发 → 髮 / 發） |
| T05 | `spelling_quiz` | 从生词本出题，判分并回写复习记录 |
| T08 | `learning_stats` | 查询次数、生词增长、7 日复习完成率 |
| T11 | `translate_on_select` | 纯本地词表，选中文字给义项 |

验收标准在 `backlog/tasks.json` 对应条目里。

## 你能改的

- `hpp/features/<你的 key>/**` —— 只有这里。

**`hpp/store.py` 是 M0 的，你只读不写。** 需要新接口 → 写 `.team/needs.md`，
说明「哪个函数、什么签名、为什么」，然后放弃这轮。别自己加，加了就冲突。

## 红线

1. **不引第三方库**：图表用 Canvas 自绘，繁简表自己带 JSON，不用 OpenCC。
2. **绝对不联网**。任何「查一下在线词典」的想法都否掉。
3. **不改 `readings`**，你只在 `annotate()` 里往 `items` 上加字段，或者在自己的面板上画。
4. **除零要防**：统计类模块最容易被「0 条生词」打崩。
5. **窗口变窄不能崩**：所有面板都要能被压到很窄，用 `grid` + `weight`，
   别写死像素宽度堆一排按钮。
6. 数据表体积守 `data_budget_kb`，文件头写来源。

## 开工六步

1. 抄 `hpp/features/tone_contour.py` 的结构（它带面板 + annotate + 设置项）。
2. T02 用 `annotate()` 往每个字挂 `{"trad": "繁", "variant": ...}`，
   面板负责展示；T05/T08/T11 用 `panel()` 出界面。
3. T05/T08 依赖 M0 的 T04，**开写前先读 `.team/store-api.md`**。文件不在就等，
   先做 T02。
4. `self_check()` ≥ 3 条真检查（能失败的检查）。数据类模块至少检一条「样例字能在表里查到」。
5. `python tools/gate.py --stage fast` 全绿。
6. `python tools/ship.py --task T0x -m "feat(<key>): <做了什么> (T0x)"`。

## 判分容错（T05 最容易做错的地方）

用户输入 `han4`、`hàn`、`han`、`Hàn`、`han4 `（尾空格）都算对。
归一化顺序：去空白 → 小写 → 数字调号转带调 → 比不带调形式 → 比带调形式。
容错规则做成配置项（`spelling_quiz_strict`，默认关），别写死。

## 特别提醒

- **T02 的数据**：常用 3000 字单字映射 + 至少 20 组一简对多繁例外词。
  单字映射可以压成「简繁同长字符串对」放两个常量里，别写成 3000 行 JSON。
- **T08 的图表**：用 `Canvas.create_line` / `create_rectangle` 画，颜色从 `self.app.colors` 取。
- **T11 的词表**：≥ 5000 条、≤ 1 MB，独立 JSON 文件放模块目录里，方便后续替换。
