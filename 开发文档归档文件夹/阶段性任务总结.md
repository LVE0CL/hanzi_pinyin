# 阶段性任务总结 · 汉字拼音浮窗 Hanzi Pinyin Popup

> 覆盖范围：第 1 次（v1.0.1）→ 第 2 次（v1.1.0）→ 第 3 次（v1.2.0）三轮迭代。
> 本文只陈述**已经落地并自测通过**的事实；未实现的部分在第四节如实标注。
> 当前版本：**1.2.0**，配置 schemaVersion = **4**，许可证 MIT。

---

## 一、软件定位

一个常驻 Windows 托盘的**本地汉字辅助工具**，解决"不认识这个字，想知道它念什么"这一个具体问题：

- 微软输入法的手写面板只给汉字，不给拼音；
- 这个小工具补上后半段：把汉字变成**带声调的拼音**，能听、能复制。

设计取向：**单一用途、本地优先、零联网**。全部拼音计算在本地完成（pypinyin 词典），
朗读走系统 SAPI，选区读取走系统 UI Automation，不向任何服务器发送文字。
跨平台代码保留（Tk + pynput + pystray），但只在 Windows 10/11 上做过完整验证。

## 二、已实现功能与实现方式（按迭代分期）

### 第 1 次迭代 · v1.0.1 —— 从"能用"到"好放"

| 功能 | 实现方式 / 关键技术 |
| --- | --- |
| 汉字 → 带声调拼音，多音字全列 | `pypinyin` 的 `heteronym=True` 拿到全部读音，再用 `phrases_dict` 词组词典反查过滤掉生僻又音；整句送进去做上下文消歧（"重庆" → chóng qìng，"银行" → yín háng） |
| 三栏式注音显示（拼音在上、汉字在下） | 自绘 `RubyView`：按 `Font.measure()` 计算格宽、按格子 `place()` 定位，主窗口与迷你浮窗共用同一套渲染，避免两份逻辑走偏 |
| 托盘常驻 | `pystray` + PIL 现画图标（"拼"字圆角方块），`run_detached()` 跑在独立线程；菜单：首页 / 设置 / 退出 |
| 双击 `Ctrl` 唤起 | `pynput.keyboard.Listener` 自建双击状态机，带按下去重与 400 ms 时间窗 |
| 无边框自定义标题栏 | `overrideredirect(True)` + `<ButtonPress-1>/<B1-Motion>` 拖动；`×` 退出 / `□` 最大化 / `−` 隐藏到托盘；最大化走 `SPI_GETWORKAREA` 避开任务栏 |
| 统一设置界面 | 声明式 `SETTING_GROUPS` 注册表驱动渲染（bool / int / choice 三类控件），左侧分组导航、右侧可滚动内容区 |
| 配置持久化 | `config.json` 落在 `%APPDATA%\HanziPinyinPopup`，临时文件 + `fsync` + `os.replace` 原子写入，带 `schemaVersion` 与 `migrate()` 迁移钩子 |
| 单实例 | 绑定 `127.0.0.1:47653`；第二次启动连接后发 `show` 并退出 |

### 第 2 次迭代 · v1.1.0 —— "顺手就查"

| 功能 | 实现方式 / 关键技术 |
| --- | --- |
| US5 八向拖动改大小（缺陷修复） | 四周贴 8 个几像素宽的 `tk.Frame` 热区，`cursor` 随方向切换（`sb_h_double_arrow` / `size_nw_se` / `size_ne_sw`），拖动时按方向重算 `geometry`；最大化时隐藏热区。**关键坑**：Tk 的 grab 是窗口级，必须 `grab_current().grab_release()` 才能解，否则热区会把后续鼠标事件全部吞掉 |
| US6 选中文字后双击弹迷你浮窗 | `pynput.mouse.Listener` 监听双击，用 `uiautomation` 的 `TextPattern.GetSelection()` **直接读选区、不碰剪贴板**；读不到时才在确认光标位于文本控件（EditControl / DocumentControl / TextControl）后，用「备份 → Ctrl+C → 还原」兜底，避免在资源管理器里双击变成复制文件 |
| US7 迷你浮窗 | 独立 `Toplevel`：贴光标定位（下方放不下自动翻到上方）、可拖动、可固定（pin）、`-alpha` 逐帧淡入淡出、超时自动收起 |
| US8 朗读增强 | 一次 PowerShell 调用枚举 SAPI 嗓音并缓存；常驻进程里 `SelectVoice()` 切嗓音；点单字朗读；抓取选区前后备份/还原剪贴板 |
| US9 标调方式与多音字点击 | 内部统一用带调字符串，显示前经 `pypinyin.contrib.tone_convert` 转 `han4` / `han`；点字循环切换主读音并朗读 |

### 第 3 次迭代 · v1.2.0 —— "好看、好控、好定制"

| 功能 | 实现方式 / 关键技术 |
| --- | --- |
| US10 设置图标统一为齿轮 | 首页入口用 Pillow 现画齿轮位图（Tk 在 Windows 上不渲染 ⚙ 字形），托盘菜单用齿轮字符前缀 |
| US11 首启引导 + 模块化开关框架 | 首次启动（`first_run=true`）弹一次性引导页，勾选后写入 `modules` 并置 `first_run=false`；模块表 `MODULES` 一处定义 15 项，设置页与引导页共用；未启用模块不显示入口 |
| US12 内置手写板 | 米字格 `Canvas`（随尺寸自适应网格）+ 笔画记录 / 撤销 / 清空；识别接入 **Windows 系统手写面板**（微软同款识别器），把焦点交给输入框后唤起面板，出字即落进输入框并自动注音；`handwriting_engine` 预留 `offline` ONNX 分支（缺模型时明确提示） |
| US13 5 套 VS Code 风主题 + 背景覆盖 | 集中式 `THEMES` 配色表（Dark+ / Light+ / Dark Blue / Light Blue / Monokai），每套统一定义 11 个色键；`theme_colors()` 支持自定义背景色，按亮度自动推导面板/悬停/边框色并切换黑/白文字；切换时整体重建界面（保留输入内容），无需重启 |
| US14 图钉切换置顶 | 标题栏顺序 `📌 │ − │ □ │ ×`；图钉用 Pillow 画两态位图（实心高亮 = 置顶，描边 = 不置顶），点击即切 `always_on_top` 并写盘 |
| US15 快捷键重构 | ① 空字符串 = 禁用，监听器 `disabled` 直接不启动；② 删除「抓取选中文字」热键与配置项，`migrate()` 主动清除旧 `hotkey`；③ 新增「选中双击模式 = 鼠标 / 键盘」，键盘模式复用双击状态机监听功能键（默认 `Shift`）；④ 保存时若功能键与唤起键相同，弹「是否互换」确认框，确定交换、取消回退输入 |
| US17 点浮窗外自动关闭 | `pynput.mouse.Listener` 捕获**跨应用**点击，坐标判定放到 Tk 线程执行（`winfo_*` 不能跨线程读）；已 pin 的浮窗不受影响，与超时淡出互不干扰；带 350 ms 出生缓冲避免"打开它的那一次双击"把自己关掉 |
| FR1 过滤非中文/非标点 | 新增 `filter_text()`：正则保留 CJK 与标点白名单，其余（英文、数字、符号、emoji、空白）丢弃；在 `analyze()` 入口统一过滤，浮窗与迷你浮窗共用；开关 `filter_non_han` 默认开启。回归：`Hello 你好 123！` → 只标注「你好！」 |
| 配置迁移 | `schemaVersion` 3 → 4：清理 `hotkey`，补齐主题/背景、快捷键模式、模块表、首启、手写引擎、过滤器等字段；`dark` / `light` 自动映射到 `dark_plus` / `light_plus`；模块表每轮对齐（幂等） |
| 质量保障 | `--selftest` 扩到 20 项无界面断言（过滤、主题、模块、迁移、快捷键空值）；另有 43 项界面级验收脚本覆盖 US10–US17，全部通过 |
| 文档与发布 | 重写 README（功能/截图/配置/限制/路线）；本文档留档；PyInstaller 打包说明与 GitHub Release 流程写入开发文档第七节 |

### 关于 15 个可选模块的边界

本轮交付的是**框架与开关**：引导页、设置页、`modules` 配置、入口显隐、依赖延后加载都已就位。
**模块内部功能（笔画动画、字帖、SRS、自测、声调图、自定义词库、翻译、HSK、Ruby 导出、
反向查字、注音符号、繁简对照、统计、云同步）尚未实现**，将在后续迭代按开关逐个交付。
本期唯一落地内部逻辑的可选模块是「手写功能（handwriting）」。

## 三、技术栈

| 层次 | 选型 |
| --- | --- |
| 语言 / 运行时 | Python 3.10+（开发环境 3.14），单文件应用 `hanzi_pinyin.py` |
| 界面 | 标准库 `tkinter`（无边框窗口、Canvas 滚动区、`place` 精确排版） |
| 拼音引擎 | `pypinyin`（`Style.TONE` + `heteronym` + `phrases_dict` + `tone_convert`） |
| 全局输入监听 | `pynput`（键盘双击、鼠标双击、外部点击、触摸键盘快捷键兜底） |
| 托盘 | `pystray` |
| 图形资源 | `Pillow`（应用图标、齿轮、图钉、下拉三角，全部运行时绘制，不依赖外部图片） |
| 语音 | Windows SAPI，通过常驻 PowerShell 进程调用（base64 传文本避免编码问题，`CREATE_NO_WINDOW` 不弹黑框） |
| 选区读取 | `uiautomation`（UI Automation `TextPattern`），剪贴板兜底 |
| 持久化 | JSON + 原子写入 + `schemaVersion` / `migrate()` |
| 打包 | PyInstaller `--noconfirm --windowed` |
| 协作流程 | Git 语义化提交（按 US 编号）、里程碑 Tag、GitHub 远程同步 |

线程模型：Tk 主线程只做界面；按键 / 鼠标 / 托盘 / 朗读 / 识别全在后台线程，
回调一律经 `queue.Queue` 入队、主线程每 60 ms 轮询执行；退出时 `after_cancel` 全部 job 再 `destroy`。

## 四、已知限制与后续路线

### 已知限制

1. **平台**：图钉、手写、SAPI、UIA 都是 Windows 路径；macOS / Linux 有代码分支但未实测。
2. **15 个模块只有开关框架**，内部功能未实现（见第二节末尾）。
3. **手写识别的边界**：Windows 11 已移除 Tablet PC 的 `MSINKAUTLib` COM 组件；WinRT 的
   `InkRecognizerContainer` 能在 PowerShell 5.1 里拿到识别器列表，但异步结果对象无法投影
   回 .NET（`__ComObject` 无法 QI），因此改为复用**系统手写面板**（同一个微软识别器）完成识别。
   好处是质量等同输入法、零维护；代价是识别发生在系统面板而非内置画布上。
   离线 ONNX 引擎只留了接口与模型路径，本期未随包提供模型。
4. **朗读嗓音**取决于系统已安装的语音包；只有中文女声时「男声优先」会退回女声。
5. **选区读取**依赖目标程序暴露 UI Automation 文本模式，个别自绘控件读不到。
6. **打包**需要 Python ≤ 3.13（PyInstaller 对 3.14 支持滞后）。

### 后续路线

- v1.3.x：把 15 个模块按优先级逐个落地（笔画动画 → 生词本 SRS → 声调五度图 → Ruby 导出）；
- 训练 / 集成离线手写模型（CASIA-HWDB 等公开数据集），让内置画板可以独立出字；
- 设置页内直接预览主题色板与字号效果；
- macOS / Linux 实机适配（托盘、朗读、选区读取三处替换实现）；
- 多语言界面（`language` 字段已预留）。
